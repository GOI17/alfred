Install Alfred

Homebrew installs the versioned Alfred CLI and its app-like, human-first installer. The curl bootstrap remains available. Use arrow keys, checkbox-style toggles, text inputs, and mouse clicks where supported. Harness choices show installed/not-installed status and support selecting multiple targets before Alfred writes anything.

Preview first. The default path writes no files. Use flags only for automation after the choices are already known; live harness config still requires explicit human approval.

Requirements

  • Homebrew for the versioned macOS/Linux package
  • Node.js 22+ (node -v)
  • pnpm 10+ (optional) — only for monorepo development
  • One of: opencode, Pi, Codex, Claude, VSCode
  • macOS, Linux, or WSL2
OpenTUI with a safe fallback. The guided installer prefers a checksum-verified OpenTUI executable, using the same native terminal framework that powers OpenCode. Node 22+ remains supported: when a compatible OpenTUI artifact or runtime is unavailable, Alfred automatically uses its dependency-free Node terminal adapter with the same decisions and approval gates.

Install with Homebrew

Install Git, GitHub CLI (gh), and Homebrew on the target computer first. Your GitHub account needs read access to both private repositories: GOI17/homebrew-alfred (the tap) and GOI17/alfred (the source). Authenticate over HTTPS, configure Git to use that account, and verify access before installing:

zsh — Homebrew 
gh auth login --hostname github.com --git-protocol https
gh auth setup-git --hostname github.com
gh api repos/GOI17/homebrew-alfred --jq .full_name
gh api repos/GOI17/alfred --jq .full_name
git ls-remote https://github.com/GOI17/homebrew-alfred.git HEAD
git ls-remote https://github.com/GOI17/alfred.git HEAD

# Continue only when both API and Git checks succeed
brew tap GOI17/alfred
brew install GOI17/alfred/alfred
alfred version
alfred setup # guided, preview-first configuration

# lifecycle
brew update
brew upgrade GOI17/alfred/alfred
brew uninstall GOI17/alfred/alfred
Use the full formula name. Plain brew install alfred resolves to the unrelated Alfred macOS application cask. Homebrew installs Alfred's commands but does not write live harness configuration; that remains gated by alfred setup.

Homebrew access troubleshooting

Homebrew maps the tap GOI17/alfred to the repository GOI17/homebrew-alfred. The old GOI17/homebrew-tap name currently redirects to it. Use the canonical name for new installs; changing capitalization does not fix authentication. The explicit brew tap GOI17/alfred step registers the tap before installation.

gh auth setup-git --hostname github.com configures the Git credential helper for GitHub on this computer. A working GitHub browser session or API request does not guarantee that Homebrew's Git subprocess can authenticate. Never paste tokens into commands, repository URLs, or issue reports.

ResultMeaning and next step
A repository API check returns 404 A private repository can hide its existence from an account without access. Verify the account selected by gh auth status --hostname github.com and ask the owner to confirm read access to both repositories. A 404 alone does not establish a publication failure.
API checks pass but git ls-remote fails Check the HTTPS Git credential helper and account permissions on this computer. Re-run the hostname-scoped setup command above and both Git checks. API metadata access alone is insufficient.
Tap access works, source Git access fails The formula downloads private Git source from GOI17/alfred. Obtain read access to that repository; permission to read only the tap is insufficient.
Both repositories are accessible, but the formula is absent or stale Inspect the published formula and the release/publisher checks below. If the remote formula is current, run brew update and inspect brew info GOI17/alfred/alfred. If the tap is missing locally, run brew tap GOI17/alfred first.

With authenticated repository access confirmed, check formula presence and inspect its source tag and revision:

gh api repos/GOI17/homebrew-alfred/contents/Formula/alfred.rb --jq .path
gh api -H 'Accept: application/vnd.github.raw+json' repos/GOI17/homebrew-alfred/contents/Formula/alfred.rb

For maintainers: compare the formula's tag: and revision: with the matching stable release and source tag. Replace vX.Y.Z below with the formula's tag. For an annotated tag, compare the peeled ^{} commit with the formula revision. A missing file after confirmed repository access, a mismatched pin, or a failed publisher job warrants a publication investigation. 

gh release view vX.Y.Z --repo GOI17/alfred --json tagName,isDraft,isPrerelease,url
git ls-remote https://github.com/GOI17/alfred.git 'refs/tags/vX.Y.Z' 'refs/tags/vX.Y.Z^{}'
gh run list --repo GOI17/alfred --workflow release-please.yml --limit 10
gh run list --repo GOI17/alfred --workflow release-homebrew-tap.yml --limit 10
# Replace RUN_ID with the run for the matching release
gh run view RUN_ID --repo GOI17/alfred --json status,conclusion,jobs,url

Automatic releases invoke the publisher within the Release Please run; manually published releases and manual dispatch use the tap workflow. Inspect the publisher job, not just the overall run status. If Actions access is restricted, ask a maintainer to perform these checks. These commands only inspect state; publishing or retrying a release is a separate maintainer decision.

Choose an edition

For human installs, start with the guided flow: curl -fsSL https://raw.githubusercontent.com/GOI17/alfred/main/install.sh | sh. The installer still accepts flags for automation and CI.

EditionWhat it installsWhat you need
coding Core, agents, skills, runtime profiles, opencode/Codex adapters, eval gates. Node 22+ and your coding harness.
memory Alfred Memory, server/client/MCP/OpenAPI, external AI adapters, console. SQLite for local coding agents or Postgres for human/web agents.
full The complete Alfred operations system: coding + Memory components. Node 22+, harness, and Memory storage configuration.

Option A — coding edition

The fastest path. Perfect for coding harness operations without forcing Memory setup.

zsh — install 
# Guided human-first install; starts preview-first
curl -fsSL https://raw.githubusercontent.com/GOI17/alfred/main/install.sh | sh

# Force the dependency-free compatibility backend for diagnostics
curl -fsSL https://raw.githubusercontent.com/GOI17/alfred/main/install.sh | ALFRED_INSTALL_TUI_BACKEND=node sh

# Automation fallback when choices are already known
curl -fsSL https://raw.githubusercontent.com/GOI17/alfred/main/install.sh | sh -s -- --edition=coding --name=acme --harness=opencode,codex-cli --apply

# The TUI previews runtime profiles before activation
Profile strategy: runtime profiles / decide later
Active profile : work / personal / custom
Harness        : opencode

# The installer prints the validation plan for the selected edition
Validation     local capability checks · preview files · approval gates

The coding edition includes packages/profile-manager so the same agent can have separate work, personal, or client profiles across machines without hand-editing harness config.

Model assignment after setup

Alfred setup does not prompt for model assignments or create, replace, or modify ~/.alfred/models.json. Model selection remains a user-owned runtime or standalone reconfiguration decision after setup.

setup boundary 
# Setup leaves any existing assignment byte-for-byte unchanged
Model assignment : not part of alfred setup
Provider calls   : 0

Option B — Memory edition

Use Alfred Memory from ChatGPT, Claude, Gemini, or coding agents.

  1. If you already created a tenant in the Memory app, choose Use existing tenant. Alfred will not create another tenant; clients reuse ALFRED_MEMORY_BASE_URL and ALFRED_MEMORY_API_KEY.
  2. For a new self-hosted tenant, create a Postgres database and copy its connection string, such as postgres://user:pass@host/db?sslmode=require.
  3. Run the guided installer and choose the Memory edition. Pick Postgres for shared/human/web memory, Local SQLite for one-machine coding use, or Decide later for a no-tenant preview.
zsh — install (web) 
# Guided install: choose Memory or full in the TUI
curl -fsSL https://raw.githubusercontent.com/GOI17/alfred/main/install.sh | sh

Approve, then write

Alfred never writes harness config without your approval. When the installer finishes detection, it prints a preview like:

preview 
# Alfred install preview
Harness detected : opencode
Adapter status   : executable-translation-spike
Files to write   : 7
  + .opencode/agents/orchestrator.md
  + .opencode/agents/developer.md
  + .opencode/agents/qa.md
  + .opencode/skills/architecture-docs/SKILL.md
  + .opencode/skills/typescript-project/SKILL.md
  + opencode.json
  + AGENTS.md (merge)

Apply changes? [y/N]

Review the list first. The root installer writes no files unless you choose apply in the TUI or pass --apply in automation; harness config still remains preview-only until a human explicitly copies or applies those generated artifacts.

Verify the install

Use local checks instead of assuming a global CLI binary exists:

verify 
node -v                     # Node 22+
test -d ~/.alfred/installs/default # default suite install target

Uninstall

uninstall 
curl -fsSL https://raw.githubusercontent.com/GOI17/alfred/main/uninstall.sh | sh

# Homebrew package
brew uninstall GOI17/alfred/alfred

The uninstaller removes the installed package tree, never touches your project files, and asks before deleting the SQLite database.
